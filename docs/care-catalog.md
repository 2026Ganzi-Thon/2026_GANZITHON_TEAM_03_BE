# 돌봄 기본 데이터와 분류 API

프론트 요청의 돌봄 행동 16개와 분류를 추가합니다.

- V13__add_care_action_category.sql은 care_actions.category VARCHAR(30) NOT NULL DEFAULT '기타'를 추가합니다. ERD 변경사항도 이 컬럼 정의와 같습니다.
- V14__seed_care_actions.sql은 없는 기본 행동을 신규 보상 양털 4개, active=true로 등록합니다.
- 이름이 같은 기존 행동의 ID·보상·설명·표시 순서·활성 상태를 보존합니다. 기본 행동과 이름이 일치하고 category가 기타이면 분류를 채웁니다.
- 기존 완료·양털 거래가 참조하는 ID는 유지합니다.

GET /api/v1/care-actions의 항목에 category를 추가합니다. 값은 움직이기·마음돌봄·쉬어가기·일상가꾸기이며, 그 밖의 기존 항목은 기타입니다. 기존 응답 필드와 displayOrder·ID 정렬은 유지합니다. 신규 항목의 description은 null입니다.

```json
{"data":{"items":[{"careActionId":"DB 발급 ID","name":"물 한 잔 마시기","category":"움직이기","description":null,"rewardAmount":4,"displayOrder":1}]}}
```

V10(고민 제목)·V11(섬 꾸미기)·V12(감정 기본 데이터)와 번호 충돌을 피하도록 V13·V14를 사용합니다. 배포 DB에 더 높은 버전이 먼저 적용되지 않도록 V10 → V11 → V12 → V13 → V14 순서로 통합·배포합니다. 이 브랜치는 감정 변경 없이 최신 develop에서 분리했습니다.

검증은 전용 로컬 MySQL에서 데이터 생성·수동 설정 보존·중복 방지, category 응답, 돌봄 적립·회수·동시 재시도를 확인합니다. 테스트용 돌봄 ID는 기본 데이터와 분리합니다.
